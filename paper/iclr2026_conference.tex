\begin{abstract}
Speculative Decoding (SD) is a paradigm that exploits the memory-bound nature of Large Language Model (LLM) generation to hide the compute cost of drafting and running multiple tokens through a single model forward pass \citep{leviathan2023fast, chen2023accelerating}. While modern SD techniques like Medusa and Eagle have been optimized for GPUs (which have high operational intensities), these methods rely on assumptions that don't hold for edge devices \citep{cai2024medusa, li2024eagle}. In this work, we evaluate the independent head (Medusa) and sequential feature (Eagle) architectures on Gemma 3 270M \citep{google2024gemma}, comparing performance between Nvidia A100 GPUs and Apple M-Series Silicon \citep{apple2024m4}. We identify that the deep speculation trees optimized for GPUs \citep{miao2024specinfer} cause a bottleneck shift on edge devices: the increased computational overhead of the expanded attention masks exceed the latency savings of reduced memory access, resulting in a 3--5$\times$ slowdown on Apple Silicon \citep{williams2009roofline}. Conversely, we demonstrate that on-device inference requires minimalist single-token-single-head speculation strategy, restoring a 9--28\% speedup on the highly optimized MLX \citep{hannun2023mlx}.
\end{abstract}

\section{Introduction}

The proliferation of on-device AI has driven the adoption of Small Language Models (SLMs) such as Gemma 3 270M as alternatives or supplements to cloud-based inference for easy workloads. However, widespread adoption is still limited by high latency that breaks the interactiveness of their applications. Furthermore, increasing response speeds expands the frontier of what model sizes are viable to be run locally.

While SLMs have significantly reduced parameter counts, the autoregressive nature of transformer generation is fundamentally memory-bound \citep{williams2009roofline}. To balance the memory bottleneck and increase speed, Speculative Decoding (SD) with Multi-Token Prediction (MTP) has emerged as a popular paradigm \citep{leviathan2023fast, chen2023accelerating, gloeckle2024better}. Methods like Medusa (independent heads) \citep{cai2024medusa} and Eagle (sequential feature extraction) \citep{li2024eagle} exploit the high arithmetic operational intensity of GPUs (e.g., Nvidia A100s). They draft multiple future tokens in a single forward pass to convert a portion of the memory-bottleneck to a compute bottleneck, while being lossless.

On GPUs, the cost of these deep multi-token speculation trees \citep{miao2024specinfer} is effectively hidden due to their massively parallel compute optimized nature. This is in stark contrast to mobile chips: the A100 40GB has an FP16 Operational Intensity Threshold (ratio of max FLOPs to max memory bandwidth) of approximately 201 FLOPs/byte \citep{nvidia2020a100}, whereas the Apple M4 Pro chip's GPU only has about 62 FLOPs/byte \citep{apple2024m4}, more than 3$\times$ less.

In this work, we run 3 core experiments to understand and fix the mismatch between current MTP practices and on-device inference. First, we implement and train Medusa and Eagle on Gemma 3 270M using self-generated trajectories, reproducing strong speedups for the standard GPU setting. Second, we transfer and evaluate the models' optimized single-batch inference performance on Apple Silicon \citep{hannun2023mlx}. Lastly, we identify the bottleneck on-device: the deep speculation trees that inflate attention and verification compute to the point that the overhead dominates the increase in throughput. Thus, we devise a simple, minimalist, hardware-aware recipe: single-token, single-head speculation that keeps compute small enough to accelerate inference.

\section{Methodology}

We use Gemma 3 270M as our base SLM because it is a common target for on-device deployment and still has enough breadth to warrant and be capable of speculative decoding. To investigate the hardware-specific performance spectrum, we implement two foundational MTP paradigms: Medusa (lightweight) \citep{cai2024medusa} and Eagle (much heavier) \citep{li2024eagle}.

\subsection{Architecture Variants}

\paragraph{Medusa}
Medusa (independent heads) first introduced the MTP speculative decoding paradigm to LLMs. Medusa augments the base model with $K$ independent, lightweight draft heads. Concretely, each head consists of a single linear layer followed by a SiLU activation and an LM-head, predicting future tokens $t+1, t+2, \ldots, t+k$ conditioned on the backbone's final hidden state $h_t$. While Medusa has a simple design, the individual LM heads would each take 170M parameters, resulting in a model more than 4$\times$ the original parameters for the default 5 heads. Thus, we modified this with a LoRA \citep{hu2021lora} on top of the base model's LM head and later tried removing the LoRA LM head altogether. Medusa also relies on a large tree-attention mask (up to 80 nodes) during the verification pass to maximize token acceptance on GPU \citep{cai2024medusa, miao2024specinfer}.

\paragraph{Inference Verification}
Given a prompt prefix $T_{:t}$, the backbone produces a hidden representation $h_t$ \citep{leviathan2023fast}. Each head produces its output distribution of tokens. The top tokens at each head are then structured greedily to create a tree of potential completions \citep{cai2024medusa}. This is input into the original model using a modified ``tree-attention'' to properly mask and attend the sequence, so all parts of the completion tree may be run in parallel through the model \citep{miao2024specinfer}. These drafts are then verified through this forward pass where only the token completions matching the backbone's greedy choice are accepted; the rest are discarded \citep{chen2023accelerating}. The furthest accepted token's hidden state is used as input to the next iteration of Medusa predictions \citep{cai2024medusa}.

\paragraph{Eagle}
Eagle (Sequential Feature Extrapolation) builds off of Medusa by using a consolidated, autoregressive single-layer transformer. It uses a linear layer to pre-process the hiddens from the beginning, middle, and end of the model and inputs this into the transformer. The transformer produces depth-$k$ predictions by recursively concatenating the previously predicted token's embedding to the input to the next step. This produces a tree of logically coherent sequences of tokens rather than the attempt to discretize the joint distributions created because Medusa's heads are independent, however, this is at the cost of sequential compute during drafting \citep{li2024eagle}.

\subsection{Training Rigor and Loss}

To ensure draft heads align with the base model's distribution, we moved beyond generic corpora like FineWeb-EDU \citep{penedo2024fineweb} and used our own self-generated trajectories. We generated 100k completions by prompting Gemma 3 270M with the OpenHermes 2.5 dataset \citep{teknium2023openhermes}. This in-distribution dataset ensures the model draft heads learn the nuances of the model and enable KL loss.

While we initially utilized Cross-Entropy (CE) loss due to its simplicity and use in Medusa-1, later experiments showed that Kullback-Leibler (KL) Divergence improved performance. By training the heads to match the backbone's soft-target probability distribution rather than hard labels, we enrich the supervision and increase acceptance rates.

\subsection{Evaluation Setup}

We report decoding throughput (tokens per second, tps) under single-batch inference on both Nvidia A100 GPUs and Apple Silicon via MLX (M4 Pro 20-core) \citep{hannun2023mlx}. We sweep draft tree size, the number of speculative candidates, to capture regime changes across hardware. Large trees are empirically effective on GPU, while on-device inference prefers shallow speculation.

\subsection{GPU Baseline}

We first validate that multi-token prediction (MTP) provides meaningful throughput gains for small models in the standard GPU setting. We trained Medusa and Eagle variants on our self-distilled trajectories and evaluated them using single-batch decoding throughput \citep{cai2024medusa, li2024eagle}. Across both GSM8K and HumanEval, we observe that stronger draft alignment from KL divergence loss correlates with higher acceptance and higher throughput: switching Medusa to KL-only training increases throughput from 35.9 to 49.5 tps on GSM8K and 33.6 to 49.2 tps on HumanEval (Tables~\ref{tab:gsm8k}--\ref{tab:humaneval}) \citep{cobbe2021gsm8k, chen2021humaneval}.

The Eagle results show a preference for depth. On HumanEval, throughput rose from 34.2 to 50.5 to 56.2 tps with depth of 1, 2, and 3, respectively. However, at this small model, 270M scale, Eagle's superior multi-token prediction performance of 2.4 additional tokens for depth 3, compared to Medusa's approximately 1.0, only translates to a speedup of between 0.0 to 7.0 tps because it's a much heavier prediction module. Even for the high operational intensity A100s, Eagle is heavy.

\subsection{Edge Failure}

We then port the same MTP setup to Apple Silicon using MLX, again measuring single-batch throughput \citep{hannun2023mlx}. However, the base setup that excelled on GPU was dramatically slower on-edge, between 3--5$\times$ slower relative to the MLX baseline.

The profiling explains this story in depth. As tree size grows, verification becomes dominated by the backbone and LM-head compute. The workload of the expanded tree attention used in the backbone slows down the latency significantly more than the speculated generations increase it. Concretely, a tree size of 80 is 3.17$\times$ more expensive for the M4 Pro, while it's just 1.12$\times$ more expensive for the A100 \citep{apple2024m4, nvidia2020a100}. The effect is similar for LM head compute time. Thus, 80\% of the time was spent on the backbone pass; this was the largest source of the slowdown. This shows that although the Apple Silicon chip is still memory-bound given the sub-linear scaling, the tradeoff for additional compute is much more expensive than on GPU.

\subsection{Minimalist Speculation}

Given the edge failure mode, we use the sweep of the profiled tree and context size performance to find the compute-optimal regime. Theoretically, the sweep's optimal tree size for the M4 Pro is 4. However, this was an idealized experiment that did not cover cache misses caused by re-arranging the KV cache and the Python overhead for manually restructuring and formatting tree attention in MLX. This could be optimized in the future, but currently, our results show that a tree size of 2 improves throughput most consistently from 204.7 to 223.4 tps (+9.1\%) on GSM8K, while larger trees degrade performance \citep{cobbe2021gsm8k}. On HumanEval, the tree size of 2 yields an improvement from 97.8 to 125.3 tps (+28.1\%), while a tree size of 3 did see an improvement up to 151.1 tps \citep{chen2021humaneval}. However, the consistently positive performance of the tree size of 2 is preferred as GSM8K was across the board more difficult for our MTP modules to exceed baseline.

Consequently, we present a hardware-aware minimalist recipe for on-device inference: single-token, single-head speculation. By removing the complexity of tree attention and multiple heads to create the lightest MTP module possible, this approach restores positive gains, achieving speedups of 9.1\% on GSM8K \citep{cobbe2021gsm8k} and 28.1\% on HumanEval \citep{chen2021humaneval} using the Apple M4 Pro \citep{apple2024m4}. Our findings suggest that effective on-device speculation demands a departure from GPU-centric intuition and that minimizing verification overhead is far more critical than theoretical token yield.
